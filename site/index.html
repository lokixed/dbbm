Database backups you run yourself

DBBM backs up MySQL, PostgreSQL, MongoDB and Firestore to a local volume and Google Drive, on a schedule, with a web UI. One container, one docker compose up.

Run it in 2 minutes Docker Hub Source on GitHub

What you get

Four engines

MySQL, PostgreSQL, MongoDB and Firestore, with per-database selection and connection tests.

Two copies, verified

A local volume and Google Drive. Every file is checked with SHA-256 and a manifest.

Schedules and retention

Cron-style schedules, missed-run catch-up, keep-last and keep-days retention.

Restore wizard

Restore into a registered source, choose some tables or collections, and watch a live log.

Optional encryption

Encrypt each backup with age. The server only ever holds public keys.

Alerts and audit log

Slack, email and webhook alerts, heartbeat URLs, and an audit log of every change.

Quick start

You need Docker with Compose. The image is built for linux/amd64.

1. Create the master key and the folders

The master key encrypts every stored credential. Keep a copy of it somewhere safe: losing it means re-entering all credentials.

mkdir dbbm && cd dbbm
(umask 077; openssl rand -base64 32 > app_key.txt)
mkdir -p data backups

2. Create docker-compose.yml

Set user to your own user and group IDs (id -u and id -g) so the folders are readable and writable.

services:
  dbbm:
    image: lokixed/dbbm:1.0.0-rc.1
    restart: unless-stopped
    user: "1000:1000"
    ports:
      - "127.0.0.1:8080:8080"
    environment:
      APP_SECRET_KEY_FILE: /run/secrets/app_key
      TZ: UTC
    volumes:
      - ./data:/data
      - ./backups:/backups
    read_only: true
    tmpfs:
      - /tmp
    cap_drop:
      - ALL
    security_opt:
      - no-new-privileges:true
    secrets:
      - app_key

secrets:
  app_key:
    file: ./app_key.txt

3. Start it

docker compose up -d
curl http://127.0.0.1:8080/healthz

Open http://127.0.0.1:8080, create the admin account, then add a source, a destination and a job, and press Run now.

The port is bound to 127.0.0.1 on purpose. To use it from other machines, put Caddy or Traefik in front for HTTPS and set COOKIE_SECURE=true. Run only one container per ./data folder: the container owns the scheduler.

Reaching your databases

Put the container on the same Docker network as your databases and use the service name as the host. For a database on the Docker host, use host.docker.internal (add extra_hosts: ["host.docker.internal:host-gateway"] on Linux) and make sure the database allows the connection. Use a read-only database user for backups.

Image tags

The same image is on Docker Hub (lokixed/dbbm) and GitHub Container Registry (ghcr.io/lokixed/dbbm). It is signed with cosign (keyless) and carries an SBOM.

TagMeaning
X.Y.ZOne release. Pin one of these in production.
X.YThe newest patch of that minor version.
latestThe newest release.
edgeThe latest commit on main that passed CI. May change at any time.
sha-<commit>One exact commit.

Releases are automatic: every time CI passes on main, the next version is calculated from the commit messages. See Releases and the changelog.

Upgrading

docker compose pull
docker compose up -d

Back up ./data first. The app migrates its own database when it starts, and running backups are marked as interrupted when the container stops.

Configuration

VariablePurpose

DATA_DIRMetadata database and run logs. Default /data.
BACKUP_DIRWhere backup files go. Default /backups.
TZContainer time zone. Each job has its own schedule time zone.

PUBLIC_BASE_URLBase URL used in notification links.

Google Drive and Firestore

  • Google Drive uses rclone inside the image. Create an OAuth client, publish the consent screen (apps left in Testing get tokens that expire after 7 days), then paste the token in Destinations.
  • Firestore needs the Cloud Firestore API enabled, a Cloud Storage staging bucket, and a service account with roles/datastore.importExportAdmin plus read and write on the bucket. The app calls Google's REST APIs directly, so no extra tool is installed.

The full guide is in the README and operations guide.

What is inside the image

mysqldump (MySQL 8.4 client), pg_dump 18, mongodump and mongorestore, rclone and age, with a Python (FastAPI) backend and a React web UI. It runs as a non-root user with a read-only root file system and no extra Linux capabilities.

Credentials are encrypted at rest and are never returned by the API. Read the security notes for what is and is not protected.
